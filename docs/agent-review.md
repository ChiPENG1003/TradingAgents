# Agents 与决策工具检查

本次检查范围：现有单目标股票 live 决策流程、工具分工、上下文传递和组合持仓输入；未实现多股票投资建议。

## 结论

现有 agents 足够完成当前阶段的任务。优先改善证据传递和确定性校验，比增加一个通用 LLM agent 更直接。Portfolio Manager 原本没有直接接收四份完整报告作为决策 prompt（完整报告仅用于记忆检索），但仍接收研究计划、交易建议、风险历史、持仓重复描述和记忆，缺少统一长度边界。

Token 数不会仅因上下文变长而指数增加。在每轮追加固定长度文字、重复发送全部历史的简化情形下，累计输入类似 1+2+…+R，即随轮数平方增长。此仓库原本已对部分历史截断，所以不能直接断言实际增长是平方或指数。长上下文可能使关键证据利用变差，参见 [Lost in the Middle](https://aclanthology.org/2024.tacl-1.9/)，但不能据此声称本次改动已提高交易准确率。

现有 `back_test/logs/token_usage/MSFT_2026-02-09.json` 中 PM 输入为 3,161 tokens，输出为 7,543；Market Analyst 累计输入为 17,873。这只是既有回测样本，不能代表当前 live 模式，且不同模型输出统计可能包含推理 tokens。没有进行付费 live 前后对照，尚无真实节省比例或决策正确率结论。

## 职责和工具

| 角色 | 现有数据/工具 | 检查与分工 |
| --- | --- | --- |
| Market Analyst | OHLCV、批量指标、options chain、verified market snapshot | 保留；价格、波动率、成交量与技术位由它提供。批量指标和工具轮次限制已有实现。 |
| News Analyst | 公司/宏观新闻、FRED、options chain | 保留催化剂与宏观背景职责；FRED 缺失或历史数据不可用时不能用记忆替代数值。 |
| Social/Sentiment Analyst | 新闻、options chain | 实际是新闻与期权情绪分析，并没有独立社交平台数据；与 News 有重叠，适合设为可选，暂不增加社交 agent。 |
| Fundamentals Analyst | 财务概况、资产负债表、现金流、利润表 | 保留财务健康和基本面风险职责；不负责短期入场价。 |
| Conflict Detector | 提取上述报告的 factor signals，Python 计算冲突与行情锚点 | 复用这个已有节点，把证据摘要和锚点共享给 Trader、风控和 PM，无需增加摘要 LLM 调用。 |
| Bull / Bear Researcher | 报告、冲突、记忆；无行情工具 | 保留正反证据辩论，避免让其自行声称取到了新数据。 |
| Research Manager | 辩论与记忆，结构化 ResearchPlan | 负责论点、事实、反证、失效条件，要求简短交接。 |
| Trader | 研究计划、共享证据、行情锚点、记忆 | 负责具体执行价位和方案；修复此前虽读取报告变量、却未把报告证据交给其决策 prompt 的问题。 |
| Aggressive / Conservative / Neutral Risk | Trader 方案、共享证据、资本背景、各方最新意见 | 负责收益空间、下行风险与平衡校验。此前主要只看 Trader 文案，却被要求引用报告，现在获得实际摘录和锚点。 |
| Portfolio Manager | 精简交接、锚点、冲突、组合背景 | 解决分歧并生成单 ticker 最终方案，Python 校验资金与股份。 |

没有新增 LLM agent。未来真正开始多股票研究时，才值得加入组合配置职责（跨股票相关性、行业暴露、统一预算）和订单执行职责；本次均未实现。News/Sentiment/Market 都请求期权工具，仍有工具输出进入多个模型上下文的重叠；未来可以将这些原始数据统一预取，但本次没有重写数据抓取层。

## 已完成的修复

1. PM 的研究计划限 2,200 字符，Trader 建议限 2,400 字符，每个风控角色最新意见限 1,400 字符，两条记忆各限 600 字符。省略处明确标注；原文与历史保留在 state/report 中。字符数不是 tokenizer 的 token 数。
2. 风控 prompt 不再同时接收累计历史和重复的最新发言，而是平等保留三个角色的最新意见，要求保留尚未解决的关键反证。补齐共享证据、来源和已有计算锚点。
3. 复用 Conflict Detector 的同一份行情锚点；PM 不再重复获取/计算。核心数据缺失时 HOLD，缺失价格用 null，不伪造 1.0。
4. 修正“目标股票未持仓 = 全 NAV 可投入”的错误，以及 CLI 传 nav、表格读 equity 导致比例缺失的问题。
5. JSON 自动读取完整持仓背景，Python 执行可用现金、组合上限、累计加仓与方向限制。成本与市值明确区分，不研究其他持仓。
6. 修复 Sentiment agent 要求调用 `get_options_chain`、但其 ToolNode 未注册该工具的接线错误，并校验四个 analyst 的工具绑定均有对应执行入口。
7. 止损和止盈分支分别计算，避免顺序执行 CLEAR 后错误消耗止盈分支股数；表格展示校验后的结构化数据。

## 局限与验证

长度限制是有损摘录，保留首尾不能保证中间所有反证都进入 PM；这也是要求上游将未解决反证写入简短交接的原因。LLM 的简短输出要求不是硬性推理 token 上限。是否影响正确率，需要固定数据、模型与研究深度的对照评估。

验证使用 mock 模型和本地数据，覆盖 JSON 校验、自动读取与刷新、CLI 问题跳过、组合/现金上限、风险分支、证据交接和核心数据缺失保护；不调用真实券商或付费模型。三个既有 frozen feature 测试依赖本机未提供且被 gitignore 的 `back_test/features/AAPL/*.json`，不能在当前工作区完成。
