# Live 单股票建议：读取完整持仓

在项目的 `portfolio/` 文件夹内保存一个 JSON，例如 `portfolio/holdings.json`。每次 live 分析会读取文件，自动取得总 NAV、目标股票数量与平均购买价，不再询问这三项。目标股票不在列表中时，其持仓为 0，其他股票仍计入组合背景。

文件夹可通过 `TRADINGAGENTS_PORTFOLIO_DIR=/你的/持仓目录` 指定；Python API 也可在 graph config 中传入 `portfolio_dir`。显式传给 `propagate(..., holdings_info=...)` 的账户数据优先于自动读取。

## 最简格式

```json
{
  "total_portfolio": 100000,
  "holdings": [
    {"ticker": "AAPL", "quantity": 100, "avg_buy_price": 180},
    {"ticker": "MSFT", "quantity": 50, "avg_buy_price": 350}
  ]
}
```

`total_portfolio` 是现金加全部持仓**当前市值**的净资产总额，不是初始投入或股票成本。`avg_buy_price` 是每股平均成本，同一 ticker 多个批次应先合并数量、计算加权平均成本。支持小数持仓，当前交易建议使用整数股；不足一股的余额由账户实际持仓管理。

购买价不足以计算当前持仓比例或可用现金。只提供最简格式仍会跳过提问，并生成目标股票的分析和已有仓位管理建议；其他持仓只展示成本信息与市值缺失状态。**现金未知时，不输出有资金支持的新增买入股数，BUY 会降为 HOLD，并说明缺少 cash。**

## 可选字段：更准确的比例和加仓额度

```json
{
  "total_portfolio": 100000,
  "currency": "USD",
  "cash": 55000,
  "max_position_pct": 30,
  "holdings": [
    {"ticker": "AAPL", "quantity": 100, "avg_buy_price": 180, "market_price": 220},
    {"ticker": "MSFT", "quantity": 50, "avg_buy_price": 350, "market_price": 460}
  ]
}
```

- `cash`：当前可用于买入的现金。提供它后，即使其他股票没有 `market_price`，也能按已知现金限制买入；未知市值占比仍明确标注。
- `market_price`：这份快照的每股市价，仅用于账户估值，不会触发其他股票的新闻、指标或基本面分析。所有持仓都有市价时，可以省略 `cash`，系统用 NAV 减全部市值计算现金；不会用购买价计算现金。
- `max_position_pct`：目标股票占总 NAV 的上限，默认 100。例子中的 30 只是格式演示，不是对你的投资比例建议；已有仓位超过上限时禁止继续加仓，但不会仅因该字段自动清仓。
- `currency`：账户计价货币，默认 USD。本阶段要求 NAV、现金、所有价格和目标股票报价使用同一货币；尚未实现自动汇率换算，不能直接混合美元和港元等报价。

目标股票当前占比使用分析流程取得的行情锚点价格，其他股票使用账户快照中的价格。行情与快照可能时间不同，报告是参考估算，文件应由你或账户同步程序保持更新。

## 读取与决策规则

- 空目录或未找到 JSON：沿用手工录入，并可额外输入可用现金；留空则不生成新增买入股数。非法 JSON、重复 ticker、非有限/负数金额、已知市值与现金超过 NAV、多个 JSON 等情况会明确报错，不会静默换用其他账户。
- CLI 在录入阶段加载，并在分析启动前重读选中的文件。一个分析流程使用一致快照；不在分析中途混用文件的新版本。不自动连接券商、不监控文件变化、不修改你的快照。更新程序应先写临时非 `.json` 文件，再原子替换正式文件。
- Python 计算现金限制、目标持仓上限、已知其他持仓占用、累计首仓/加仓限制；不能通过拆成多行绕过加仓额度，也不会假设先卖出其他股票来筹资。
- 股票分析和建议只针对用户选择的 ticker。其他持仓仅提供数量、估值和占比背景；没有多股票研究、调仓或订单执行功能。
- 报告的每行“占 NAV”是该行金额的比例，并单独展示目标股票当前占比及所有买入成交后的参考占比。止损与止盈为互斥分支，分别按当前实际持股计算；未成交买单不作为可卖持仓，成交后应重新分析。
