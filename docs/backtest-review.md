# Backtest 可行性检查与条件订单

本次结论：当前架构可以验证“LLM 分类市场状态，Python 制定和执行条件计划”这一混合策略。它不是让 LLM 每天直接决定订单。现有回测仍不足以证明 LLM 带来超额收益；指标过滤是否有效，需要与固定规则和不使用 LLM 的基线比较。

## 三个时间尺度应独立

| 时间尺度 | 实际代码和修改 |
| --- | --- |
| 历史信息长度 | `_compute_short_term_market_anchors` 默认最多 260 根日线，结构分析已有短期形态及 50/200 日均线。不是只看七天。本次增加 MACD/KDJ/BOLL 数值，最低 60 根连续有效 OHLC 日线用于这些执行指标预热。 |
| LLM 复审间隔 | CLI 默认每 5 个交易日生成新计划，可以缩短为 1 天；复审间隔不应同时截断指标历史。 |
| 订单有效期与执行频率 | 已有逐日回放，但旧首仓 TTL=2、加仓 TTL=1 会过早放弃等待。新生成计划将两者设置为复审周期；有效期内每个交易日重新检查条件。显式 CLI TTL 参数仍可覆盖。 |

七天可以是计划有效期，却不应是 MACD/BOLL 等指标的全部历史。一天复审也可以使用一年数据。历史足够长仍不代表市场信息全面：MACD、KDJ、BOLL 主要是同一价格序列的不同变换，不能当成三次独立确认。

## 已修复的实质问题

1. **只有计划日分析指标，成交日主要检查价格。**现在将可执行条件保存为 `execution_conditions`，执行引擎逐日检查前一完整交易日的数据。条件未满足会保留订单，直到触发、过期或被新计划替换。每日检查不调用 LLM。
2. **加仓确认在生成日失败就删除计划。**默认改为保留有条件的加仓计划，按保存的关键价位，等待连续收盘站稳。`defer_add_confirmation_to_execution=False` 可还原旧逻辑。新的执行规则使用连续收盘确认；并不声称复刻旧的“回踩或收盘站稳”两种情形。
3. **新买入当天不执行止损。**现在新仓/加仓成交后，如果日内最低价触及止损，按保守不利路径处理。日线不能证明盘中先后关系，因此不假设当天免于止损；同时触及止盈时不会选择有利路径。
4. **首次建仓丢失止盈、减仓子订单。**现在建仓成交后启用原计划中的止盈/防御减仓单，不必等待下一次 LLM 复审。子订单的非硬止损成交从下一根日线开始检查，避免猜测买入当天的高低价顺序。
5. **已有持仓不能独立更新止损。**新复审计划可以上调止损，无需先成交加仓单；保留禁止放宽已有止损的约束。
6. **行情与持仓时点相差一天。**旧迭代回测使用复审日收盘行情、前一交易日账户。现在回放旧计划至复审日收盘，随后形成新计划，次日开始执行。
7. **启用量能确认但缺数据时直接放行。**现在缺少确认数据会继续等待，并计入缺失/延迟统计；不会静默变成价格单。
8. **未实现收益被误当成交易反馈。**`end_of_backtest` 的未平仓估值不再进入已实现盈亏、交易数和胜率。CLI 回测/参数优化的收益与回撤以初始资本为起点，包含首日损益；年化期间数改为相邻权益观测的实际间隔数。
9. **行情源多返回未来行时的防御。**计算锚点前再次按分析日过滤，保证模型不会因为缓存返回额外行而获得未来行情。

## 指标规则与时序

实现位于 `back_test/technical_conditions.py`，采用明确的本地计算约定：

- MACD：EMA(12)−EMA(26)，信号线 EMA(9)，柱值 DIF−DEA；`bullish` 要求柱值 > 0，`rising` 要求柱值比上一日上升。
- KDJ：9 日 RSV，K/D 初始值 50，以 1/3 递推平滑，J=3K−2D；`bullish` 要求 K>D，`cross_up` 要求最近完整日刚发生上穿。不同软件的初始化约定可能不同，不声明与 TA-Lib 数值完全一致。
- BOLL：20 日均值 ± 2 倍总体标准差（ddof=0）；`above_mid` 要求收盘在中轨之上，`inside_bands` 要求收盘在上下轨之间。
- 成交量比：最近完整日成交量 / 此前 20 日平均成交量，分母不包含被比较的当日。旧的独立 `--entry-min-volume-ratio` 参数使用其原有包含当日的均量定义；做对照时应明确使用哪一种，不混淆。
- 同一订单中配置的条件采用 AND；未启用的指标不强制参与。此实现为多头确认规则，没有实现做空策略。

日线下的准确时序是：

```text
周一收盘：LLM 使用截至周一的历史数据，形成价格、仓位和条件计划
周二开盘前：读取周一已完成日线的量和指标；若未确认则继续等待
周三开盘前：读取周二已完成日线；确认后，周三价格触及计划价才可成交
后续交易日：重复检查，直到计划过期或被新计划替换
```

因此这不是“周三收盘后发现量够大，再假装周三低点已经买入”。如果要在同一天实时满足价格、累计量和指标后立即成交，必须使用分钟/逐笔数据并重新定义盘中指标和成交规则。日线 OHLC 无法恢复这种先后顺序。[Backtrader 的成交约定](https://www.backtrader.com/docu/order-creation-execution/order-creation-execution/)、[关联保护订单](https://www.backtrader.com/docu/order-creation-execution/bracket/bracket/)。

## 使用方法

新生成回测计划默认 `backtest_confirmation_profile="volume_macd"`：量比 ≥1 且 MACD 柱值 >0；这是一个可检验的初始规则，不是已验证最优参数。可以在 graph config 中切换：

```python
config["backtest_confirmation_profile"] = "volume_macd_kdj_boll"
config["review_cadence_trading_days"] = 5
```

保存的策略会包含类似字段：

```json
{
  "execution_conditions": {
    "entry": {"min_volume_ratio": 1.0, "macd": "bullish", "kdj": "bullish", "boll": "above_mid"},
    "add": {"min_volume_ratio": 1.0, "macd": "bullish", "hold_above_price": 100.0, "close_hold_days": 2}
  },
  "signal_ttl_trading_days": {"entry": 5, "add": 5}
}
```

上述是附加字段示例，仍需原有 v3 的 ticker、as_of_date、entry、stop_loss 等字段。`hold_above_price` 为生成日保存的关键价位，不是每天偷偷重选价位。

回放已有策略，可显式覆盖新指标条件：

```bash
python -m back_test.run_backtest --ticker ORCL --start 2026-01-01 --end 2026-05-28 \
  --confirmation-profile volume_macd_kdj_boll \
  --entry-signal-ttl-trading-days 5 --add-signal-ttl-trading-days 5
```

三个配置：`price_only`、`volume_macd`、`volume_macd_kdj_boll`。默认不传 CLI profile 时使用保存的计划；旧 JSON 未保存条件时仍没有新增指标过滤。`price_only` 覆盖新增的条件模块，原有止损、风险、跳空等引擎规则仍生效。999 TTL 表示优先使用计划 TTL；旧文件未保存 TTL 时仍沿用 999，回放旧文件建议显式指定有效期。

回测报告新增 `buy_deferred_conditions`、`buy_condition_data_missing`、`same_bar_protective_stops`、`indicator_timing` 等字段，区分“策略没有机会”和“行情缺失导致无法确认”。

## 要验证 LLM 是否有效，仍需解决的事项

这些是当前数据和研究流程的实际限制，本次没有把它们包装成已解决的问题：

- **财报时间戳不是公告时间。**当前 `filter_financials_by_date` 按财务期间结束日过滤，无法保证投资者当时已看到该报表。财报必须使用真实发布日期、历史可得版本；FRED 宏观数据也需要核对历史修订/vintage。否则全信息回测存在泄漏风险，增加指标不能修复。
- **模型自身可能知道历史结果。**向 LLM 提示 as-of 日期不能消除训练记忆。优先冻结模型输出做前向纸面记录；历史回测只能在此限制下解释。
- **旧策略与新实验共用目录。**生成器和历史阶段读取仍使用按 ticker 的目录。正式实验应使用干净、隔离的策略/特征副本，避免旧运行日期或不同参数样本混入；当前未全面改造运行目录管理。
- **成本和成交能力。**手续费、滑点仍可配置且默认是 0。正式验证必须按实际市场设定成本，并做成本压力测试；日线引擎没有实现盘口、排队、成交量参与率和部分成交，不适合据此证明大资金策略可执行。
- **策略规则本身有偏好。**已有规则限制止盈价下调、止盈低于成本，以及亏损后的冷却。它们是待检验的交易假设，不是量化真理；本次保留了这些约束。
- **比较必须保持同样数据与资金路径。**至少对比纯规则、LLM 状态+纯价格执行、LLM+量/MACD、LLM+更多指标。若启用订单再生成，应核对 `strategies_regenerated`、冻结特征可用性及缺失计数；不能在未成功再生成时宣称参数有效。
- **不能凭七天或少量交易选参数。**使用滚动训练/验证/测试，考虑跨区间持仓和指标预热，固定最终测试集。反复尝试指标组合会导致过拟合，参考 [The Probability of Backtest Overfitting](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf)。本次未声称新过滤器改善收益。

## 验证结果

136 项相关测试通过，包括条件延迟成交、AND 语义、指标预热、前缀一致性（追加未来行情不改变过去指标）、成交日收盘量不影响当日入场、建仓保护订单、独立止损更新、账户反馈和策略序列化。

另外运行了依赖本机 ORCL 历史样本的订单再生成测试，其中两项失败：旧保存订单与当前缓存重算价格不一致，以及样本中没有成功加载足够的冻结特征进行再生成。已在单独进程使用 Git HEAD 的原始引擎和原始 state manager 复查，同样失败；本次没有修改这些本机样本来制造通过结果。

未调用付费 LLM、未提交真实订单，也没有完成真实数据的收益 A/B 评估。当前测试证明的是执行逻辑和时间一致性，不是投资获利能力。
